= Ammitto Swiss sanctions data

image:https://github.com/ammitto/data-ch/actions/workflows/fetch.yml/badge.svg["Fetch Data", link="https://github.com/ammitto/data-ch/actions/workflows/fetch.yml"]

This repository stores Swiss sanctions-list records as YAML for Ammitto.
The State Secretariat for Economic Affairs (SECO) publishes the official
consolidated list of individuals, companies, organisations and objects such
as vessels; Ammitto generates one file per listed target in `processed/`.

== Source

* Publisher: State Secretariat for Economic Affairs (SECO), Switzerland
* List page: https://www.seco.admin.ch/en/searching-for-subjects-sanctions
* File downloaded (XML consolidated list): https://www.sesam.search.admin.ch/sesam-search-web/pages/downloadXmlGesamtliste.xhtml?lang=en&action=downloadXmlGesamtlisteAction

SECO publishes the complete list of sanctioned individuals, companies and
organisations, with an XML specification (XSD) and value lists on the list
page.

== Contents

`processed/` holds one file per target, named after its SECO identifier
(`ssid`): `processed/ch-100173.yaml` is target 100173.

`processed/_index.yaml` lists every file, with the time of the last fetch.

[cols="1,1,3"]
|===
| Key | Type | Meaning

| `ssid` | string | SECO identifier of the target
| `sanctions_set_id` | string | Identifier of the sanctions set the target belongs to in the SECO XML
| `individual` | map | Present when the target is a person
| `entity` | map | Present when the target is a company or organisation
| `…identity.ssid` | string | SECO identifier of the identity
| `…identity.main` | string | `'true'` for the main identity
| `…identity.names` | list | Names: `name_type` (`primary-name`, `alias` or `formerly-known-as`), `quality` (`good` or `low`), `lang` and `name_parts`
| `…names[].name_parts` | list | Parts of the name: `order`, `name_part_type` (such as `given-name`, `family-name`, `father-name` or `whole-name`) and `value`
| `…identity.day_month_year` | map | A date published with the identity (for persons, the date of birth): `year`, `month` and `day`, each only when known; a date can have no year
| `…identity.addresses` | list | `address_details` and `zip_code`; null in some files
| `…justification` | string | SECO's statement of reasons, where published
|===

Keys written with `…` sit inside the `individual` or `entity` block.

`sources/` holds a hand-curated sample entry and supporting reference data
(document types, organisations), with their schemas in `schemas/`.
`reference-docs/` holds a dated copy of the SECO XML. The daily fetch updates
neither; `processed/` is the list.

`downloaded/` is empty.

== Using the data

Clone or download this repository and run either example from its root
directory. The Python example requires PyYAML
(`python3 -m pip install PyYAML`).

Ruby:

[source,ruby]
----
require "yaml"

Dir.glob("processed/ch-*.yaml").sort.each do |path|
  record = YAML.safe_load_file(path)
  target = record["individual"] || record["entity"]
  next unless target

  name = target["identity"]["names"].find { |n| n["name_type"] == "primary-name" }
  text = name["name_parts"].sort_by { |p| p["order"] }.map { |p| p["value"] }.join(" ")
  kind = record["individual"] ? "individual" : "entity"
  puts [record["ssid"], kind, text].join("\t")
end
----

Python:

[source,python]
----
import glob
import yaml

for path in sorted(glob.glob("processed/ch-*.yaml")):
    with open(path, encoding="utf-8") as f:
        record = yaml.safe_load(f)
    target = record.get("individual") or record.get("entity")
    if not target:
        continue
    name = next(n for n in target["identity"]["names"] if n["name_type"] == "primary-name")
    parts = sorted(name["name_parts"], key=lambda p: p["order"])
    kind = "individual" if "individual" in record else "entity"
    print(record["ssid"], kind, " ".join(p["value"] for p in parts), sep="\t")
----

The same list, harmonized with the other sources into JSON-LD:
https://www.ammitto.org/api/v1/sources/ch.jsonld

== Updates

The `Fetch Data` workflow (`.github/workflows/fetch.yml`) downloads the list
every day at 07:45 UTC and commits any change to `processed/`. It runs with
`--prune`, so a target SECO has removed is deleted here on the next fetch.

== Maintaining the data

The link:.github/workflows/fetch.yml[fetch workflow] uses Ruby 3.3 and Bundler.
To refresh `processed/` locally, install the link:Gemfile[Gemfile] dependencies
and run the same command from the repository root:

[source,shell]
----
bundle install
bundle exec ammitto fetch ch --format yaml --output-dir processed --verbose --prune
----

This regenerates `processed/` and removes entries absent from the fetched
list. Fetching and parsing are implemented in the
https://github.com/ammitto/ammitto[Ammitto gem].

For edits to the curated samples and reference data in `sources/`, run
`bundle exec rake validate`. The link:Rakefile[Rakefile] checks only those
source files against `schemas/`.
